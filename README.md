# BEST — Boltzmann Equation Solver for Thermalization

[Comput. Phys. Commun. 327 (2026) 110295](https://doi.org/10.1016/j.cpc.2026.110295) · [arXiv:2603.28848](https://arxiv.org/abs/2603.28848)

[Talk (Paris-Saclay Astroparticle Symposium 2026)](https://best-hep.github.io/talks/20261028_astro_YOON.pdf)

A Python framework for solving the momentum-resolved Boltzmann equation for arbitrary *n* → *m* scattering processes using adaptive Monte Carlo integration.

Since v1.3.0 the kinematics are exact (two-body generation of the last pair) instead of the finite-width energy delta function of the paper; see the [changelog](CHANGELOG.md) for the conventions.

## Overview

BEST evaluates the collision integral directly in 3*n*_total − 8 dimensions using the [Vegas](https://vegas.readthedocs.io/) adaptive Monte Carlo algorithm, with energy and momentum conservation exact for every sample: the last two free legs of a process are generated by two-body kinematics (PDG, *Kinematics* review), so no delta function is ever approximated. It is designed for cosmological applications where the standard number-density (integrated) Boltzmann equation is insufficient and the full phase-space distribution must be tracked.

The loss and the gain of a grid point are integrated on the same samples, so near equilibrium their difference is free of the noise they share.

Key features:

- **Arbitrary *n* → *m* processes** — 2→2, 2→3, 3→2, and higher multiplicities, with integration dimensionality determined automatically
- **Identical-particle decomposition** — Correct treatment of processes with unequal multiplicities on each side (e.g. ϕϕ ↔ ϕϕϕ), essential for energy conservation
- **Full quantum statistics** — Bose enhancement and Pauli blocking without approximation
- **Massive particles** — Arbitrary masses, including time-dependent masses for phase transitions
- **Multiple coupled species** — Simultaneous evolution of several interacting species
- **Cosmological expansion** — Comoving momenta with built-in radiation domination
- **Exact kinematics** — No width parameter and no on-shell projection: the n-body phase space is sampled exactly, which also makes the Monte Carlo variance small enough that 10⁵ samples per grid point suffice for most 2→2 and 1→2 rates
- **Exponential time integrators** — `exprb` (diagonal, Hubble-paced steps to freeze-out), `exprb2` (second order, resolves the departure of a stiff species from its moving equilibrium), `exprb_seq` (Gauss–Seidel splitting for a stiff elastic process next to slow chemistry) and `exprb_full` (the full Jacobian of the collision operator, for species that exchange particles with a bath that they must keep thermal)
- **CP violation** — A process and its CP conjugate with their own |M|², integrated on the same Vegas samples so that the difference of a particle's and its antiparticle's distributions is free of the noise they share, the reverse direction of each taken from the other by CPT or given explicitly; species declared with their antiparticles
- **Custom collision terms and medium effects** — Terms given directly on the grid (splitting kernels, relaxation terms, sources) next to the Vegas processes; masses and matrix elements may depend on the current distributions
- **Semi-analytical 2→2 benchmark** — Exact energy conservation following [Ala-Mattinen et al. (2022)](https://arxiv.org/abs/2201.06456)
- **MPI parallelization** — Near-linear scaling to hundreds of cores

## Installation

No installation of BEST itself is needed: clone the repository and set up the
dependencies. The route used for development is a conda environment with
`mpi4py` from conda (it brings its own MPI library) and `vegas` from pip
(it installs `gvar` with it):

```
git clone https://github.com/best-hep/best.git
cd best
conda create -n best python=3.13 numpy mpi4py
conda activate best
pip install scipy vegas
```

Check MPI before anything larger — this should print 0 and 1:

```
mpirun -np 2 python -c "from mpi4py import MPI; print(MPI.COMM_WORLD.Get_rank())"
```

On a cluster, build `mpi4py` against the system MPI instead: load the MPI
module, then `pip install mpi4py`; `python -c "from mpi4py import MPI;
print(MPI.Get_library_version())"` should name that MPI. `vegas` comes from
pip as above.

## Quick Start

### 2→2 elastic scattering

```python
import numpy as np
import os
from besthep import BEST


# ======================================================================
# Matrix element
# ======================================================================
lam = 1.0   # L = -(lam/4!) phi^4

def matrix_element_squared(momenta):
    """Bare |M|^2 = lam^2; the symmetry factor for identical particles is applied by the solver."""
    return np.full(momenta.shape[2], lam**2)


# ======================================================================
# Initial condition
# ======================================================================
def init_f(r, r0=3.0, width=2.0):
    """Non-thermal sigmoid distribution."""
    return 1.0 / (1 + np.exp((r - r0) / width))


# ======================================================================
# Parameters
# ======================================================================
q_min    = 0.1
q_max    = 50.0
n_grid   = 40
mass     = 1.0
neval    = int(1e4)
dt       = 1e2
n_steps  = 100
checkpoint_file = "checkpoint.pkl"


# ======================================================================
# Setup
# ======================================================================
solver = BEST(q_min=q_min, q_max=q_max, n_grid=n_grid)

resume = os.path.exists(checkpoint_file) and solver.world_rank == 0
resume = solver.world_comm.bcast(resume, root=0)

if resume:
    history = solver.load_checkpoint(
        checkpoint_file,
        matrix_elements_squared={'2to2': matrix_element_squared})
else:
    solver.initialize_species('phi', init_f, stat='boson', mass=mass)
    solver.add_process('2to2',
                       ['phi', 'phi'], ['phi', 'phi'],
                       matrix_element_squared, neval=neval)

    history = solver.init_history()


# ======================================================================
# Evolution
# ======================================================================
for step in range(n_steps):
    solver.evolve_step(dt=dt)

    m = solver.record(history)

    if solver.world_rank == 0:
        N0, E0 = history['phi']['n'][0], history['phi']['e'][0]
        print(f"  N/N0={m['phi']['n']/N0:.6f}  "
              f"E/E0={m['phi']['e']/E0:.6f}")

    solver.save_checkpoint(checkpoint_file, history=history)
```

Run with MPI:

```bash
mpirun -np 8 python3 examples/2to2m1.py
```

`matrix_element_squared(momenta)` returns the bare |M|² of the Feynman rules,
couplings included, one value per Vegas batch point (`momenta` has shape
(n_particles, 3, N); see `examples/propagator.py` for momentum-dependent
amplitudes). |M|² is the squared amplitude with the couplings of the
Lagrangian; the symmetry factors for identical particles belong to the phase
space, as usual. The solver's convention for internal states is the
unaveraged sum over every leg, initial and final: a spin-averaged
$\overline{|M|^2}$ of the textbooks is converted by multiplying with the
initial-state degrees of freedom, $\sum|M|^2 = g_1 g_2\,\overline{|M|^2}$.
The solver divides by the degrees of freedom of the observed species
(`initialize_species(..., dof=...)`, default 2 for fermions and 1 for bosons)
and applies the symmetry factor 1/(∏ n_in,s! ∏ n_out,s!) and the leg
multiplicities itself (`add_process(..., symmetry_factor='auto')`, the
default); pass `symmetry_factor=1.0` if your |M|² already contains the factor.

`initialize_species` also accepts a `(q, f)` pair of arrays or a two-column
text file (`q f`, comoving q at a₀). A species initialized at zero is seeded
from its production spectrum at the first step (`solver.f_seed`, default
1e-10), so freeze-in runs can start from an empty species.

### Choosing a time integrator

- `heun` (default) and `euler` are explicit: adequate for short relaxation /
  thermalization problems.
- `exprb` (diagonal exponential Rosenbrock–Euler): **use this for expansion
  runs that track equilibrium over many Hubble times (e.g. freeze-out to a
  relic abundance).** There the collision rates exceed *H* by orders of
  magnitude, so explicit steppers need dt ~ 1/rate and become impractically
  expensive, while `exprb` runs Hubble-paced dt at one Vegas pass per step.
  First order, positivity-preserving; it does not remove elastic
  shape-relaxation stiffness.
- `exprb2` (two-stage exponential Rosenbrock, ETD2RK): the `exprb` predictor,
  a second rate pass at the predicted state and a φ₂ correction; second order
  at two Vegas passes per step. **Use this when the small departure of a stiff
  species from its moving equilibrium matters** (a CP asymmetry in strong
  wash-out): `exprb` leaves the species one step behind its equilibrium instead
  of the physical lag. Occupations driven below zero are set to the floor and
  reported. Validated so far on a decay into a prescribed bath
  (`scripts/check_asymmetry.py`); experimental elsewhere.
- `exprb_seq` (sequential / Gauss–Seidel exponential splitting): **use this
  when a stiff number-conserving process (elastic scattering) runs alongside
  slow number-changing chemistry** (e.g. the sub-threshold freeze-out example,
  `ann` + `el`). A single summed `exprb` step damps the slow net rate by the
  stiff Γ, suppressing the chemistry by ~Γ_stiff·dt; `exprb_seq` instead
  advances each process over the full dt with its own exponential substep,
  stiffest first, re-measuring the later processes' rates on the updated f.
  Costs 2N−1 rate passes per step for N processes; identical to `exprb` for
  a single process. First-order splitting; run with `adapt_dt=False` in
  stiff regimes.
- `exprb_full` (exponential Rosenbrock–Euler with the full Jacobian over all
  species and processes, assembled on the Vegas samples): **use this when a
  slow process feeds or drains a bath that other, stiff processes keep
  thermal** (the Majorana decay example). The diagonal methods relax the bath
  back to the equilibrium it had before the slow process acted, so number and
  energy drift; the full Jacobian carries the conserved directions and the bath
  follows the exchange. Costs one more rate pass and a Jacobian accumulation
  per step. The Jacobian is a Monte Carlo estimate, so the method is usable
  while dt·λ_noise ≪ 1 (printed as `max Re(dt J)` under `verbose`); for
  Hubble-paced steps of a very stiff process `exprb_seq` remains the method of
  choice. An entry of the Jacobian that its own Monte Carlo error does not
  resolve is set to zero (`BEST.J_SIG`, the multiple of σ; 0 disables; the
  counts are printed under `verbose`). Occupations driven below zero (empty
  tails) are set to the floor and the number moved is reported. A stiff
  process that only keeps species in equilibrium with a prescribed bath is
  better given as a custom term with its Jacobian (below) than as a Monte
  Carlo process.

```python
solver.evolve_step(dt, method='exprb')
solver.evolve_step(dt, method='exprb2')
solver.evolve_step(dt, method='exprb_seq', adapt_dt=False)
solver.evolve_step(dt, method='exprb_full', adapt_dt=False)
```

### Time-dependent masses

```python
solver.set_mass_func('phi', lambda t: 1.0 if t > 20 else 0.0)
```

The mass function and the matrix elements may read the solver, so masses and
propagators that depend on the medium are computed from the current
distributions; `solver.step_hook` is called once at the start of every step,
the place to evaluate them:

```python
def medium(solver):
    q = solver.r_grids['phi']
    f = solver.distributions_1d['phi']
    solver.m_th2 = lam / 2 * np.trapezoid(q * q * f / np.sqrt(q * q + m0 * m0), q) / (2 * np.pi**2)
solver.step_hook = medium
solver.set_mass_func('phi', lambda t: np.sqrt(m0 * m0 + solver.m_th2))
```

### Custom collision terms

A collision term that is not an *n* → *m* process with a matrix element, such as
a collinear splitting kernel with a medium-dependent rate or a relaxation
term, is given directly on the grid:

```python
def splitting(solver):
    q = solver.r_grids['g']
    f = solver.distributions_1d['g']
    gain = ...                       # d f/dt into mode q, with the statistics factors
    loss = ...                       # d f/dt out of mode q (proportional to f)
    return {'g': (gain, loss)}

solver.add_custom_term('split', splitting)
```

`func(solver)` returns `{species: (gain, loss)}` at the current distributions,
in physical time and comoving momentum, with the statistics factors inside; the
term takes part in every rate pass and every stepper like a process. Nothing
about it is checked by the solver: kinematics, statistics, detailed balance and
conservation are the author's. An optional `jacobian(solver)` returns
`{species: {species2: matrix}}` for the full-Jacobian step; without it the step
uses the diagonal −loss/f. Checkpoints restore the term by function name
(`load_checkpoint(..., custom_terms={'split': splitting})`).
`scripts/check_custom_term.py` checks the decay N → Φ l written as
one-dimensional kernels against the Vegas process.

### CP violation

By default the reverse direction of a process, output → input, is integrated
with the forward |M|² (T invariance). A process can carry its own reverse |M|²,
or be linked to its CP conjugate; species can be declared with their
antiparticles (a self-conjugate species names itself):

```python
solver.initialize_species('N', f_N, stat='fermion', mass=M, antiparticle='N')
solver.initialize_species('Phi', f_th, stat='boson', dof=2, antiparticle='Phibar')
solver.initialize_species('Phibar', f_th, stat='boson', dof=2, antiparticle='Phi')
...
solver.add_process('decA', ['N'], ['Phi', 'l'], M2_A)                               # N -> Phi l
solver.add_process('decB', ['N'], ['Phibar', 'lbar'], M2_B, cp_conjugate='decA')    # N -> Phibar lbar
solver.add_process('dl2', ['Phi', 'l'], ['Phibar', 'lbar'], M2, mesq_backward=M2_rev)
```

The reverse |M|² of a process is `mesq_backward(momenta)` if given (same
`momenta` array, input + output order); else, if the process has a CP
conjugate, the forward |M|² of the conjugate (CPT); else the forward |M|²
itself. A process whose reverse is its own CP conjugate (Φ l → Φ̄ l̄) has no
partner to take it from: give it (else it is taken T invariant), and do not
register the reverse as a second process, since every process is integrated in
both directions.

A pair is integrated on the same Vegas samples, slot by slot, so f_l − f_l̄
carries the Monte Carlo noise of order ε times the rate and not the noise of
two independent rates; the solver checks that the two processes match slot by
slot and treats the pair as one integration everywhere (quality control,
backward fallback, `exprb_seq`). There is no ε in the solver: the asymmetry is
whatever the matrix elements produce, and their consistency (CPT, unitarity,
the real-intermediate-state subtraction) is the user's. The effective set of
decays and inverse decays at order ε (Hahn-Woernle, Plümacher & Wong 2009, HPW) is
the pair above with each member's forward |M|² given as its reverse one as
well. A process with negative rates (a subtracted remainder) is stepped by the
summed steppers as long as the summed gain and loss of every species stay
non-negative; not by `exprb_seq`.

`examples/Mdecay_cp.py` runs N ↔ Φ l against the prescribed thermal bath of
HPW with l and l̄ as species, the plasma coupling of the leptons as a
relaxation term (a custom term with its Jacobian) and `exprb_full`, and reads
the asymmetry off the distributions next to the integrated reference D1, which
it reproduces within the few percent HPW find between their full and
integrated treatments. `scripts/check_conjugate.py` checks pairs and explicit
reverse |M|² against the T-symmetric reference; `scripts/check_asymmetry.py`
checks HPW's linearized formulation against an exact solution of the mode
equations.

### Checkpointing

```python
solver.save_checkpoint('checkpoint.pkl', history=history)
history = solver.load_checkpoint('checkpoint.pkl',
    matrix_elements_squared={'2to2': matrix_element_squared})
```

`save_checkpoint` is **collective**: call it from all MPI ranks (as in the
examples above). The checkpoint stores the adapted Vegas integrator state of
every MPI group, so resumed runs continue seamlessly; resuming with a
different number of momentum groups discards the integrator maps with a
warning and re-adapts. The keys of `matrix_elements_squared` are process
names (or function names); lambdas and closures are restored by process name,
a process with its own reverse |M|² by `{'name': (func, func_backward)}`. A
checkpoint restores what was there: a reverse |M|² for a process saved without
one is refused (re-register the process to change it).

## Plotting the results

```bash
python scripts/plot.py checkpoint.pkl
```

writes one figure per species: the f(q) snapshot fan plus the N/N₀, E/E₀
conservation history. The freeze-out example has its own scripts,
`plot_spectra_stfo.py` and `plot_yield_stfo.py` (run next to `checkpoint.pkl`,
no arguments). The checkpoint is a plain pickle — `state['history']` holds
per-step f and moments for custom analysis.
